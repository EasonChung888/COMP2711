接收者公开加密信息，保留解密信息

public key cryptography（公钥密码）采用 asymmetric（非对称）的密钥结构。接收者将 public key（公钥）分发给其他人，private key（私钥）只由自己保留，后面的 RSA 会用模幂实现这种分工。

发送者用接收者的公钥加密，接收者用自己的私钥还原。发送者无需先取得对方的秘密；安全目标是在公钥和密文已知时，仍难恢复私钥或明文。

相比之下，前面的对称密码依靠共同秘密参与加密与解密。这个秘密要预先分发，或通过密钥交换建立。页上的实体传递与未经认证的 DH 是前文背景，并没有列尽所有方案。

公钥可以公开，身份归属仍需认证。若攻击者递来自己的公钥并冒充接收者，发送者就可能把消息加密给攻击者；不能因某个值叫“公钥”就接受它属于声称的那个人。

RSA 的名字与公开年份

RSA 取自 Ronald Rivest、Adi Shamir、Leonard Adleman 三人的姓氏。图中除这三位外，还列出 Clifford Cocks：他曾在英国政府的保密研究中独立得到相关方案，后来才公开这段历史。

课件写的 197619761976 年需要澄清。MIT 保存的原始技术备忘录记录标为 1977 年 4 月，正式期刊论文通常列为 197819781978 年，因此原页的 197619761976 不能直接作为准确的 RSA 公开年份。

GCHQ 的历史说明确认，英国先行保密工作的相关成就于 199719971997 年公开。原页“早三年”依赖前面所用的年份，不能换一个年代后仍直接相减。

这是一页方案来源介绍，没有新加密公式。照片和出生年份不参与算法计算；后文才会用参数、加解密指数及恢复消息的证明展开 RSA 的数学部分。

公开乘积，保留因子

取两个不同的大素数 p,qp,qp,q，计算 n=pqn=pqn=pq。知道因子时相乘容易；只给 nnn 再找 p,qp,qp,q，则是 factoring（整数分解）问题，区别于前面的离散对数。

RSA 公开的是 (n,e)(n,e)(n,e)，并要求

gcd⁡(e,(p−1)(q−1))=1.\gcd(e,(p-1)(q-1))=1.gcd(e,(p−1)(q−1))=1.

持有因子的人能算出 (p−1)(q−1)(p-1)(q-1)(p−1)(q−1)，再求用于解密的指数 ddd。这里 p≠qp\ne qp=q 是所用乘积公式的条件，不能省去。

产生候选数并作素性检验，可以寻找随机大素数。这与分解任意给定大整数的信息条件不同：生成 nnn 时知道因子，不代表只看 nnn 就能轻易找回它们。

页上把 p,qp,qp,q 称为私钥材料；基本解密实际只需 ddd 和公开的 nnn。公开乘积并不允许公开因子。原页的位数与随机选择 eee 属于教学说明，不是当前实现参数建议，分解困难也不能保证任意 RSA 用法自动安全。

密钥生成与密钥保存是不同操作

PuTTY Key Generator 的这张历史截图中，进度条尚未完成，界面提示在空白区域移动鼠标以收集随机性。

随机性关系到私密参数能否被猜中。若不同用户的素数或其他秘密参数可以预测，即使 RSA 数学公式正确，秘密仍可能暴露。鼠标运动只是截图展示的一种熵来源，随意输入一些内容本身不等于完整的安全生成方案。

下方按钮分别为 Generate（生成）、Load（载入）、Save public key（保存公钥）与 Save private key（保存私钥）。生成一对密钥不等于已经保存；保存时也要分清公钥可以分发、私钥需要保密。

参数栏列出 RSA 等类型和示例位数 204820482048。这是把抽象密钥材料联系到生成、载入与保存流程的课件示例，没有新的 RSA 推导，也不是当前界面或部署参数建议，更不是要求实际在电脑上生成密钥。

公钥文件中的长字符串是什么

图中 SSH2 PUBLIC KEY 的首尾标记界定公钥数据，中间长串文字是二进制公钥材料的编码，Comment 则是说明标签。

数学上写作 (n,e)(n,e)(n,e) 的 RSA 公钥，保存成文件时还要交代算法类型、各个大整数的边界，再转换为便于保存和复制的文字。因此这里看到的是公钥的编码格式，并非两个短十进制数字，也不是加密后的秘密消息。

RSA 加密是用接收者的公钥做模幂

把消息块表示为整数 xxx，标准范围为 0≤x<n0\le x<n0≤x<n。Alice 要发给 Bob，就使用 Bob 的公钥 (n,e)(n,e)(n,e)，计算

C=xe mod n,C=x^e\bmod n,C=xemodn,

再发送密文 CCC。公钥和密文都可以被第三方看到，解密所需私密信息仍由 Bob 保留。

范围限制不可省略：模 nnn 运算会把相差 nnn 的输入合并；若直接把任意大整数当作一个消息块，就无法仅凭结果恢复它原来属于哪一段范围。

重复平方使加密只需 O(log⁡e)O(\log e)O(loge) 次模乘。原页“与密钥长度成正比”主要描述循环次数的增长；每次大整数乘法本身也有成本，因此不应把完整位运算时间简单写成只与位数一次成正比。

已知 C,n,eC,n,eC,n,e 求 xxx 称为 RSA problem。它与“已知底数、求指数”的离散对数不同：这里指数 eee 已知，未知的是底数 xxx。分解 nnn 能提供一条求私钥的路径，但不能反过来未经证明就宣称所有 RSA 反演都等价于分解。

这页是教科书 RSA 运算原语；裸公式具有确定性，不单独构成完整的安全消息加密方案。

解密指数是在另一个模数下求逆元

Bob 知道不同素数 p,qp,qp,q，所以能够算出 T=(p−1)(q−1)T=(p-1)(q-1)T=(p−1)(q−1)。选择公钥时已要求 gcd⁡(e,T)=1\gcd(e,T)=1gcd(e,T)=1，因此用扩展欧几里得算法求

de≡1(modT).de\equiv1\pmod T.de≡1(modT).

这个 ddd 就是解密指数。收到 CCC 后，Bob 计算 Cd mod nC^d\bmod nCdmodn。

这里有两个模数，不能混淆：求逆元时模的是 T=(p−1)(q−1)T=(p-1)(q-1)T=(p−1)(q−1)，实际加解密时模的是 n=pqn=pqn=pq。ddd 不是 eee 模 nnn 的逆元，也不是普通分数 1/e1/e1/e。

根据指数规则，Cd≡(xe)d=xed(modn)C^d\equiv(x^e)^d=x^{ed}\pmod nCd≡(xe)d=xed(modn)。但还不能只因为 ed≡1(modT)ed\equiv1\pmod Ted≡1(modT) 就直接把指数替换成 111；需要另外证明这些幂在模 nnn 下的周期关系。本页把 xed≡xx^{ed}\equiv xxed≡x 留待后续证明，这正是 RSA 正确性的核心。

知道 p,qp,qp,q 让 TTT 和 ddd 的计算容易；不知道因子时寻找私密信息的困难性，是安全方面的考虑。它不同于上面的代数正确性证明，不能用“解密结果正确”反过来当作安全证明。

RSA 的两种角色：保密传送与签名验证

第一种用途是传送共享秘密：Alice 用 Bob 的公钥加密一份对称密钥，Bob 用自己的私钥恢复，再由双方使用该对称密钥处理大量消息。这体现非对称方法与对称方法的分工。

第二种用途是 digital signature（数字签名）。课件用简化代数模型说明：Alice 持有私密指数 ddd，对消息整数 xxx 计算 C=xd mod nC=x^d\bmod nC=xdmodn，发送 (C,x)(C,x)(C,x)；Bob 使用 Alice 的公钥 (n,e)(n,e)(n,e) 检查 Ce mod nC^e\bmod nCemodn 是否等于 xxx。

这展示了“持有私密信息者产生、任何持有可信公钥者验证”的权限方向，与加密用途相反。但它不是完整的安全签名方案：裸 RSA 中，任何人可先任选 CCC，再定义 x=Ce mod nx=C^e\bmod nx=Cemodn，就能造出一对满足检查式的数，而无需私钥。因此不能只凭这个等式就无条件断言消息来自 Alice；实际签名还需规定消息编码、哈希和安全填充等机制。

签名也不自动保密，因为这里直接传送 xxx。若希望同时具备保密与可验证来源，可在合适协议中先签名，再用接收者的公钥加密已签名内容；验证时仍需确认公钥身份。

本页应记住的是各自使用谁的密钥、完成什么目标，以及简化公式与完整方案之间的区别。

公钥身份从哪里获得可信依据？

即使数学运算完全正确，若拿到的是攻击者冒充 Alice 的公钥，仍可能遭遇中间人攻击。本页因此追问：怎样确认这个公钥确实属于 Alice？

Certificate authority（CA，证书颁发机构）的角色，是对身份与公钥之间的绑定作签名证明。验证者不仅检查数学签名，还需要检查证书声称的身份与当前通信对象是否匹配。

接着的问题是 CA 公钥本身从哪里可信。课件用浏览器内置的信任根说明：证书链最终必须落到某个预先被信任的公钥或信任来源。否则再为每把公钥找另一把公钥背书，会无限追问下去。

原页列出的公司名称是课件当时的例子，不是当前浏览器信任库清单，也不是服务推荐。真正需要理解的是信任链结构，而不是背诵这些品牌。

最后一句带有幽默意味：密码学无法在完全没有信任起点的情况下，凭空证明整个软件环境都可信。系统必须明确其信任假设，并保护这些信任起点；公钥机制解决的是在这些假设下如何扩展可验证的身份关系。
