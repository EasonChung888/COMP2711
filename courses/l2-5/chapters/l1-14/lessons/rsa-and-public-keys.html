接收者公开加密信息，保留解密信息

public key cryptography（公钥密码）采用 asymmetric（非对称）的密钥结构。接收者将 public key（公钥）分发给其他人，private key（私钥）只由自己保留，后面的 RSA 会用模幂实现这种分工。

发送者用接收者的公钥加密，接收者用自己的私钥还原。发送者无需先取得对方的秘密；安全目标是在公钥和密文已知时，仍难恢复私钥或明文。

相比之下，前面的对称密码依靠共同秘密参与加密与解密。这个秘密要预先分发，或通过密钥交换建立。页上的实体传递与未经认证的 DH 是前文背景，并没有列尽所有方案。

公钥可以公开，身份归属仍需认证。若攻击者递来自己的公钥并冒充接收者，发送者就可能把消息加密给攻击者；不能因某个值叫“公钥”就接受它属于声称的那个人。

RSA 的名字与公开年份

RSA 取自 Ronald Rivest、Adi Shamir、Leonard Adleman 三人的姓氏。图中除这三位外，还列出 Clifford Cocks：他曾在英国政府的保密研究中独立得到相关方案，后来才公开这段历史。

课件写的 197619761976 年需要澄清。MIT 保存的原始技术备忘录记录标为 1977 年 4 月，正式期刊论文通常列为 197819781978 年，因此原页的 197619761976 不能直接作为准确的 RSA 公开年份。

GCHQ 的历史说明确认，英国先行保密工作的相关成就于 199719971997 年公开。原页“早三年”依赖前面所用的年份，不能换一个年代后仍直接相减。

这是一页方案来源介绍，没有新加密公式。照片和出生年份不参与算法计算；后文才会用参数、加解密指数及恢复消息的证明展开 RSA 的数学部分。

公开乘积，保留因子

取两个不同的大素数 p,qp,qp,q，计算 n=pqn=pqn=pq。知道因子时相乘容易；只给 nnn 再找 p,qp,qp,q，则是 factoring（整数分解）问题，区别于前面的离散对数。

RSA 公开的是 (n,e)(n,e)(n,e)，并要求

gcd⁡(e,(p−1)(q−1))=1.\gcd(e,(p-1)(q-1))=1.gcd(e,(p−1)(q−1))=1.

持有因子的人能算出 (p−1)(q−1)(p-1)(q-1)(p−1)(q−1)，再求用于解密的指数 ddd。这里 p≠qp\ne qp=q 是所用乘积公式的条件，不能省去。

产生候选数并作素性检验，可以寻找随机大素数。这与分解任意给定大整数的信息条件不同：生成 nnn 时知道因子，不代表只看 nnn 就能轻易找回它们。

页上把 p,qp,qp,q 称为私钥材料；基本解密实际只需 ddd 和公开的 nnn。公开乘积并不允许公开因子。原页的位数与随机选择 eee 属于教学说明，不是当前实现参数建议，分解困难也不能保证任意 RSA 用法自动安全。

密钥生成与密钥保存是不同操作

PuTTY Key Generator 的这张历史截图中，进度条尚未完成，界面提示在空白区域移动鼠标以收集随机性。

随机性关系到私密参数能否被猜中。若不同用户的素数或其他秘密参数可以预测，即使 RSA 数学公式正确，秘密仍可能暴露。鼠标运动只是截图展示的一种熵来源，随意输入一些内容本身不等于完整的安全生成方案。

下方按钮分别为 Generate（生成）、Load（载入）、Save public key（保存公钥）与 Save private key（保存私钥）。生成一对密钥不等于已经保存；保存时也要分清公钥可以分发、私钥需要保密。

参数栏列出 RSA 等类型和示例位数 204820482048。这是把抽象密钥材料联系到生成、载入与保存流程的课件示例，没有新的 RSA 推导，也不是当前界面或部署参数建议，更不是要求实际在电脑上生成密钥。

公钥文件中的长字符串是什么

图中 SSH2 PUBLIC KEY 的首尾标记界定公钥数据，中间长串文字是二进制公钥材料的编码，Comment 则是说明标签。

数学上写作 (n,e)(n,e)(n,e) 的 RSA 公钥，保存成文件时还要交代算法类型、各个大整数的边界，再转换为便于保存和复制的文字。因此这里看到的是公钥的编码格式，并非两个短十进制数字，也不是加密后的秘密消息。

标题里的“My”指课件演示者。这是原课件展示的公钥样本，不是用户或网站生成的密钥，也无需导入、使用或发给任何服务。编码、加密与身份认证在这里是三件不同的事。

加密消息，要用接收者的公钥

Alice 发给 Bob 的消息块先表示为整数 xxx，取 0≤x<n0\le x<n0≤x<n。使用 Bob 的公钥 (n,e)(n,e)(n,e) 计算

C=xe mod n,C=x^e\bmod n,C=xemodn,

然后发送 CCC。公钥与密文可以公开，解密秘密仍留在 Bob 手中。

消息范围决定能否完整恢复。取模会合并相差 nnn 的输入，若直接放入任意大整数，就无法仅由结果判断它原先处在哪一段范围。

重复平方让加密只需 O(log⁡e)O(\log e)O(loge) 次模乘。课件所谓“与密钥长度成正比”主要指循环次数，每次大整数乘法仍有成本，完整位运算时间不能直接这样等同。

已知 C,n,eC,n,eC,n,e 反求 xxx，称为 RSA problem。这里指数已知、底数未知，区别于离散对数。分解 nnn 可帮助求私钥，但没有据此证明所有 RSA 反演都等价于分解。

这仍是教科书 RSA 原语：裸公式是确定的，单独使用还不是完整的安全消息加密方案。

求解密指数用 T，加解密用 n

Bob 知道两个不同素数 p,qp,qp,q，便能算 T=(p−1)(q−1)T=(p-1)(q-1)T=(p−1)(q−1)。公钥指数满足 gcd⁡(e,T)=1\gcd(e,T)=1gcd(e,T)=1，因此用扩展欧几里得算法求到 ddd，使

de≡1(modT).de\equiv1\pmod T.de≡1(modT).

收到密文 CCC 后，再算 Cd mod nC^d\bmod nCdmodn，其中 n=pqn=pqn=pq。这里求逆元的模数是 TTT，实际加解密的模数是 nnn；ddd 不应理解为 eee 模 nnn 的逆元或普通分数 1/e1/e1/e。

模幂规则目前只能给出

Cd≡(xe)d=xed(modn).C^d\equiv(x^e)^d=x^{ed}\pmod n.Cd≡(xe)d=xed(modn).

要进一步得到 xxx，还须证明幂在模 nnn 下满足相应周期关系，不能仅凭 ed≡1(modT)ed\equiv1\pmod Ted≡1(modT) 就直接将指数换成 111。这部分正确性证明留在后文。

知道因子使求 T,dT,dT,d 容易，不知道因子时恢复私密信息的困难性则属于安全考虑。加解密能正确撤销，并不能反过来证明安全。

加密给接收者，签名由发送者产生

传送共享秘密时，Alice 用 Bob 的公钥加密一份对称密钥，Bob 用自己的私钥恢复，再让双方用该对称密钥处理大量消息。非对称与对称方法在这里各有分工。

digital signature（数字签名）的权限方向不同。课件以简化模型表示：Alice 用私密指数 ddd 算 C=xd mod nC=x^d\bmod nC=xdmodn，发送 (C,x)(C,x)(C,x)；Bob 用 Alice 的公钥 (n,e)(n,e)(n,e) 检查 Ce mod n=xC^e\bmod n=xCemodn=x。持有秘密者产生结果，拿到可信公钥的人可以验证。

但裸 RSA 等式并不是完整安全签名。任何人都可先任选 CCC，再令 x=Ce mod nx=C^e\bmod nx=Cemodn，造出满足检查式的一对数，无需私钥。因此仅凭等式不能无条件认定来源是 Alice，实际签名还须规定消息编码、哈希和安全填充等机制。

签名也没有将消息保密，这里直接发送了 xxx。若同时需要保密与来源验证，可在合适协议中先签名，再用接收者公钥加密已签内容；验证时仍要确认公钥的身份归属。

证书链要有一个信任起点

数学签名正确，不代表拿到的公钥就属于 Alice。若公钥实际来自冒充者，仍可能发生中间人攻击。

certificate authority（CA，证书颁发机构）对身份与公钥的绑定作签名证明。验证者既要检查签名，也要确认其中的身份与当前通信对象相符。

CA 的公钥同样需要可信依据。课件用浏览器内置的信任根说明：证书链最后必须落到预先信任的公钥或其他信任来源，否则不断另找一把公钥背书，只会无限追问。页上公司名称是当时的例子，不是当前浏览器信任库清单或服务推荐。

末句的幽默落在这个边界上：完全没有信任起点，密码学无法凭空证明整个软件环境可信。系统须明确并保护这些起点，公钥机制才在这些假设下扩展可验证的身份关系。

浏览器怎样显示证书验证结果

旧版浏览器访问学校认证站点的截图中，地址栏带 HTTPS 和锁图标，身份窗口显示网站机构、签发方 COMODO，以及连接已加密。

浏览器持有预先信任的根，验证服务器提供的证书，再把域名或机构身份显示出来。“View certificates” 是查看证书详情的入口，这里只用于解释界面，不要求执行按钮操作。

锁图标表示连接与证书验证状态，不能单独保证网页所有内容可靠，也不能代替核对通信对象。加密保护传输中的机密性，证书则绑定公钥与身份，两者的作用不同。

这张原课件历史截图展示了抽象信任链怎样出现在浏览器中，不代表该域名今天的状态、签发方或登录界面，也无需打开网站、输入任何账户信息。
