# 字符串哈希：逐字乘 31 再累加

字符串不能只看最后一个字符。课件先把字符视为整数编码，再依次执行

$$H_0=0,\qquad H_{i+1}=31H_i+s[i].$$

长度为 $\ell$ 时，展开结果是 $s[0]31^{\ell-1}+s[1]31^{\ell-2}+\cdots+s[\ell-1]$，最后取模 $n$ 作为桶编号。这是用嵌套乘加计算多项式，字符的位置也影响结果。

例如两个编码 $65,66$ 的字符串给出 $65\cdot31+66=2081$；交换顺序则为 $66\cdot31+65=2111$。比起简单求编码之和，这种方式能区分许多顺序不同的字符串，但取模后仍可能碰撞。

本页代码展示的是思路，使用时需留意三点。第一，“每个字符为 $0$ 到 $255$”是字节字符的简化模型，不涵盖所有 Unicode 字符。第二，实际 Java 字符串访问通常应写 `s.charAt(i)`，图中的 `s[i]` 是示意。第三，32 位整数溢出相当于先模 $2^{32}$ 保存位模式，再解释为有符号整数；之后 `% n` 可能为负，也不总等于无限精度多项式直接模 $n$。

因此要实现数学上标准的非负余数，可在每次乘加后用足够宽的中间类型取模；若使用固定宽度哈希，则另行把最终结果规范到合法桶编号。不要忽略机器整数与数学整数的差别。
